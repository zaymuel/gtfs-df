## Agent Brief

**Category:** enhancement
**Summary:** Add `fare_attributes.txt` and `fare_rules.txt` generation to the GTFS compiler using DFTrans `faixaTarifaria` metadata.

**Current behavior:**
Each directional metadata entry in `GET /linha/numero/{numero}` includes a `faixaTarifaria` object (`{"sequencial": 3, "descricao": "METROPOLITANA 1", "tarifa": 3.80}`), but the base GTFS specification in Ticket 04 only emits the 7 core spatial/temporal files without fare tables.

**Desired behavior:**
When `build_gtfs.py` compiles `gtfs_df.zip`, it should also parse `faixaTarifaria` from each valid line's metadata, deduplicate the fare tiers into `fare_attributes.txt` with `currency_type = BRL`, map each `route_id` to its `fare_id` in `fare_rules.txt`, and bundle both files into `gtfs_df.zip`.

**Key interfaces:**
- Input schema: `metadata[i]["faixaTarifaria"]` (`sequencial`, `descricao`, `tarifa`)
- Output tables: `data/gtfs/fare_attributes.txt` and `data/gtfs/fare_rules.txt` inside `data/gtfs/gtfs_df.zip`

**Acceptance criteria:**
- [ ] Every distinct `faixaTarifaria` present in active routes is emitted once in `fare_attributes.txt` with `currency_type` set to `BRL` and `price` formatted to 2 decimal places
- [ ] Every `route_id` in `routes.txt` that has a valid `faixaTarifaria` has a corresponding mapping row in `fare_rules.txt`
- [ ] `gtfs_df.zip` contains both `fare_attributes.txt` and `fare_rules.txt` and passes GTFS schema validation

**Out of scope:**
- Complex temporal transfer discount rules not expressible in standard GTFS v1 `fare_attributes.txt`
