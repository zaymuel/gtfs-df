# 04: End-to-End GTFS Synthesis & Linear Referencing Engine (`config.py` + `build_gtfs.py`)

**What to build:** An offline GTFS synthesis pipeline (`config.py` and `build_gtfs.py`) that reads cached raw line JSONs (`data/raw/*.json`) and master stops (`data/all_stops_df.geojson`), reprojects geometries from `EPSG:3857` to `EPSG:4326`, projects directional stops onto route polylines via `shapely` linear referencing to compute `stop_sequence`, `shape_dist_traveled`, and interpolated `arrival_time`/`departure_time` (20 km/h conventional vs. 40 km/h BRT + 30s dwell time), enforces data quality gates (`data/catalog/skipped_lines.json`), and packages a validated `data/gtfs/gtfs_df.zip` for `r5py`.

**Blocked by:** 02: Bus2 (`dfnoponto`) Schedule & Timepoint API Inspector, 03: Resilient Multi-Threaded Full-Network Raw Extraction (`extract.py` & Master Stops)

**Category:** enhancement
**Status:** ready-for-agent

- [ ] Centralizes operational parameters in `config.py`: conventional speed (`20.0` km/h), BRT speed (`40.0` km/h), stop dwell time (`30` seconds), Brasília Web Mercator scale factor ($\cos(-15.8^\circ) \approx 0.9622$), service calendar window (`20260101`–`20261231`), and file paths
- [ ] Reprojects route polylines (`shapes.txt`) and stop coordinates (`stops.txt`) from `EPSG:3857` (Web Mercator meters) to `EPSG:4326` (WGS84 decimal degrees)
- [ ] Uses `shapely` linear referencing (`LineString.project(Point)`) in `EPSG:3857` scaled by `0.9622` to order stops monotonically along each directional route (`IDA` -> `0`, `VOLTA` -> `1`, `CIRCULAR` -> `0`), computing `shape_dist_traveled` and eliminating backward-travel errors in `r5py`
- [ ] Interpolates `arrival_time` and `departure_time` in `stop_times.txt` (supporting `HH:MM:SS` $> 24\text{:00:00}$ for trips crossing midnight) using BRT fleet/route detection (`tiposOnibus` containing `"BRT"` or trunk BRT line identifiers at 40 km/h, all others at 20 km/h) plus 30s dwell per intermediate stop
- [ ] Excludes any line/direction missing valid geometry, having $< 2$ valid stops, or lacking valid departure times, recording each excluded item and its reason in `data/catalog/skipped_lines.json`
- [ ] Generates `agency.txt`, `routes.txt`, `stops.txt`, `trips.txt`, `stop_times.txt`, `calendar.txt`, and `shapes.txt` under `data/gtfs/` and bundles them into `data/gtfs/gtfs_df.zip`

## Agent Brief

**Category:** enhancement
**Summary:** Build the offline GTFS compiler with `EPSG:3857` -> `EPSG:4326` reprojection, `shapely` linear referencing, speed-differentiated stop-time synthesis (20 km/h vs. 40 km/h BRT), and quality gate logging for `r5py`.

**Current behavior:**
Raw DFTrans API responses can be downloaded per line, and the mathematical specifications for `EPSG:3857` to `EPSG:4326` conversion, `shapely` linear referencing, speed separation, and data quality filtering are settled in ADR 0001, ADR 0002, and `docs/05-methodology-data-filtering.md`, but `config.py` and `build_gtfs.py` have not yet been implemented.

**Desired behavior:**
Running `python build_gtfs.py` offline against `data/raw/*.json` and `data/all_stops_df.geojson` must deterministically synthesize all seven core static GTFS tables (`agency.txt`, `routes.txt`, `stops.txt`, `trips.txt`, `stop_times.txt`, `calendar.txt`, `shapes.txt`), package `data/gtfs/gtfs_df.zip`, and output an audit log of skipped lines at `data/catalog/skipped_lines.json`. The resulting `gtfs_df.zip` must load cleanly into `r5py.TransportNetwork` without coordinate projection, non-monotonic `stop_sequence`/`shape_dist_traveled`, or backward-time errors.

**Key interfaces:**
- `config.py`: Constants for `SPEED_CONVENTIONAL_KMH = 20.0`, `SPEED_BRT_KMH = 40.0`, `DWELL_TIME_SEC = 30`, `MERCATOR_SCALE_FACTOR = 0.9622`, `CALENDAR_START = "20260101"`, `CALENDAR_END = "20261231"`.
- `build_gtfs.py`: Offline compiler producing `data/gtfs/*.txt`, `data/gtfs/gtfs_df.zip`, and `data/catalog/skipped_lines.json`.

**Acceptance criteria:**
- [ ] All shape and stop coordinates in `shapes.txt` and `stops.txt` lie within valid Federal District WGS84 bounding box (`lat` $\in [-16.1, -15.4]$, `lon` $\in [-48.3, -47.2]$)
- [ ] For every `trip_id` in `stop_times.txt`, `stop_sequence`, `shape_dist_traveled`, `arrival_time`, and `departure_time` are strictly non-decreasing, with post-midnight trips formatted as `24:MM:SS` / `25:MM:SS` per GTFS specification
- [ ] BRT lines (identified via `tiposOnibus` or BRT line codes) are synthesized at 40 km/h and conventional lines at 20 km/h, each with 30s dwell time per intermediate stop
- [ ] Incomplete lines (missing geometry, $< 2$ stops, or empty schedules) are omitted from `trips.txt`/`routes.txt` and logged with explicit exclusion reasons in `data/catalog/skipped_lines.json`
- [ ] Automated tests inside `Python tests/` verify CRS conversion accuracy, monotonic linear referencing, post-midnight time formatting, and quality gate filtering

**Out of scope:**
- Live HTTP requests during `build_gtfs.py` execution (must operate 100% offline from cached files)
- Fare tables (`fare_attributes.txt` and `fare_rules.txt`), which are handled in Ticket 05
