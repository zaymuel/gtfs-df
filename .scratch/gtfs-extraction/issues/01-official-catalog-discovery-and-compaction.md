## Agent Brief

**Category:** enhancement
**Summary:** Replace static/third-party line catalog scraping with official active line discovery and compact the catalog schema.

**Current behavior:**
The existing line catalog contains 5,768 lines (~216 KB) of verbose objects originally scraped from the DOM of an unofficial third-party website (`brasiliamobilidade.com.br`), including redundant `slug` and `url` fields and duplicated line numbers inside `descricao`. Furthermore, querying `GET /linha/find/{termo}` with a single wildcard on the official DFTrans API is capped at 30 records (`LIMIT 30`), so new lines opened by Semob-DF can be missed if relying on a static third-party snapshot.

**Desired behavior:**
Provide an official catalog discovery routine that enumerates all currently active `Semob-DF` lines directly from official government sources (e.g., prefix expansion against DFTrans endpoints and/or the official `dfnoponto` / Bus2 master route index), retains `Semob-DF` jurisdiction filtering (`semob` urban lines vs. `ANTT` interstate lines), and stores a compact, deduplicated JSON catalog.

**Key interfaces:**
- `load_catalog()`: Should accept both the new compact catalog schema and legacy object lists so extraction runs remain backward-compatible.
- Catalog JSON schema: Deduplicated records keyed by `numero` with minimal metadata (`numero`, clean `descricao`, and jurisdiction/active status).

**Acceptance criteria:**
- [ ] Official catalog discovery retrieves all active DFTrans / Semob-DF line numbers without requiring live DOM access to `brasiliamobilidade.com.br`
- [ ] `LIMIT 30` truncation on `/linha/find/{termo}` is either bypassed (via finer-grained prefix/category enumeration) or avoided via an un-capped official index endpoint
- [ ] Interstate `ANTT` lines are excluded from the default DF urban extraction list
- [ ] The catalog JSON file size and line count are compacted by removing redundant third-party fields (`url`, `slug`, repeated prefix strings)

**Out of scope:**
- Per-line geometry and stop downloading (handled in Ticket 03)
- GTFS table synthesis (handled in Ticket 04)
